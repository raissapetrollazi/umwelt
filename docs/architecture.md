# Architecture

This document distinguishes the architecture implemented for Umwelt 0.1 from
the broader architectural direction. The v0.1 modules are intentionally narrow;
they do not freeze future APIs for spatial worlds, interventions, multimodal
data, or additional model families.

## Implemented v0.1 flow

```text
pinned COMPASS files
    -> integrity verification
    -> recorded observation dataset
         |                    |
         |                    +-> replay
         |
         +-> training subjects -> shared activity emissions
                              \-> four explicit state models
                                      |
held-out time grids and gaps ----------+
                                      v
                       replicated synthetic observations

recorded development observations -> recorded metrics --+
                                                         +-> comparison -> report
synthetic observations -----------> compact metrics -----+
```

The held-out observations provide timestamps and missingness masks to the
generator. Their recorded states and activity values are not inputs to model
fitting or state generation.

The individual-variation experiment reuses the fitted phase+duration model as a
pooled control and adds a second, separate training-population path:

```text
training subjects -> phase+duration pooled dynamics
                 \-> three smoothed offsets per training subject
                                      |
                                      v
                         empirical profile population
                                      |
held-out time grids and gaps ----------+
                                      v
                       synthetic individual populations
                                      |
                                      v
                   between-subject + temporal comparison
```

Development-subject behavior never enters profile fitting or profile selection.

## Implemented boundaries

### Observation representation

`umwelt.observations` defines source-labeled observations and regular time
series. A series is either recorded or synthetic. Missing state and activity
values must occur together and remain explicit. Dataset containers reject
duplicate subject identifiers and silent source mixing.

### Recorded data adapter

`umwelt.datasets.compass` pins the Zenodo record, expected files, sizes, MD5
checksums, DOI, license, authorship, experimental context, and label semantics.
The adapter pairs activity and sleep rows by timestamp and rejects malformed,
misaligned, negative, or internally inconsistent values.

Raw files are downloaded locally and are not committed to the repository.

### Behavioral models

`umwelt.models.circadian_markov` preserves the original phase-conditioned
first-order baseline. `umwelt.models.temporal_hazard` adds a small factorial
family in which phase and elapsed bout duration can each be enabled or disabled.
The duration mechanism is an inspectable discrete hazard with fixed bins and
hierarchical smoothing.

`umwelt.individual_variation` adds a deliberately small empirical population
mechanism on top of `phase-duration-hazard-v1`. It derives, for each training
mouse, three smoothed logit offsets relative to pooled training dynamics: sleep
occupancy, wake-leaving hazard, and sleep-leaving hazard. A synthetic individual
samples one training-derived profile and keeps it fixed for the generated
series. This is a computational population baseline, not a biological trait or
continuous hierarchical population model.

Observable activity is generated by one shared phase- and state-conditioned
zero-inflated gamma emission, bounded by the observed training maximum for its
phase/state estimate. Sharing it across the temporal ladder and the individual-
variation experiment isolates changes in state dynamics.

The original temporal models pool training subjects. The population experiment
makes one specific form of between-subject variation executable without using
development-subject behavior for calibration. None of these models infer
subjective state, personality, intention, or biological mechanism.

### Evaluation

`umwelt.evaluation` independently summarizes recorded and synthetic datasets.
It measures state occupancy, activity distributions, transition frequencies,
bout durations, daily phase profiles, between-subject sleep fraction, and
sleep-state autocorrelation at configured lags. Comparison is descriptive and
contains no implicit validation threshold.

`umwelt.temporal_evaluation` computes compact replicate metrics in one pass per
series, including empirical Wasserstein and Kolmogorov-Smirnov bout distances,
per-subject comparisons, phase-profile RMSE, and predictive simulation
intervals. Full replicate trajectories are discarded after summarization.

`umwelt.individual_lab` adds descriptive between-subject standard deviations and
ranges for selected metrics while preserving the existing temporal evaluation.
It compares the pooled and population variants using paired trajectory random
streams and a separate deterministic seed for population-profile selection.

### Experiment configuration and execution

`umwelt.config` strictly validates JSON configuration. Unknown keys are errors,
paths are resolved relative to the configuration file, training/evaluation
subjects must be disjoint, and seeds and model settings are bounded.

`umwelt.experiment` loads the recorded source once, creates the subject split,
fits the model, derives per-series seeds from the master seed, generates
synthetic series, evaluates both categories, and atomically publishes a run
directory. Existing run directories are not overwritten.

`umwelt.temporal_config` defines the separate `umwelt.temporal-lab.v1` schema so
the original configuration semantics remain stable. `umwelt.temporal_lab` fits
the four-model ladder once, derives seeds from master/model/subject/replicate
identity, evaluates each replicate, and atomically publishes compact artifacts.

`umwelt.individual_lab` reuses the temporal-lab configuration and requires an
explicit output directory. It fits the pooled phase+duration control and the
training-population profile model, generates paired replicated populations,
records every profile assignment, and atomically publishes compact artifacts.

### Artifacts and provenance

Original single-run artifacts include:

- `resolved-config.json` - the exact interpreted configuration;
- `provenance.json` - source, software, split, information categories, and time;
- `model.json` - complete fitted parameters and model assumptions;
- `seeds.json` - master and derived random seeds;
- `synthetic-observations.csv` - explicitly synthetic generated rows;
- `recorded-metrics.json` - metrics computed only from held-out recorded data;
- `synthetic-metrics.json` - metrics computed only from generated data;
- `comparison.json` - descriptive differences between those metric sets;
- `report.md` - readable interpretation boundaries, results, and limitations;
- `artifact-manifest.json` - byte sizes and SHA-256 hashes of the run artifacts.

Replicated temporal and individual-variation labs instead retain compact
replicate metrics, model-comparison summaries, seed/profile provenance,
deterministic SVG diagnostics, readable reports, and artifact manifests while
intentionally discarding full replicate trajectories.

### Headless interface

`umwelt.cli` exposes dataset download/verification, recorded replay, complete
single-run execution, replicated temporal comparison, and the individual-
variation experiment. It uses only the Python standard library at runtime.
There is no renderer or graphical dependency.

## Preserved conceptual boundaries

Future Umwelt work should remain compatible with recorded data adapters,
observations, replay, behavioral models, synthetic organisms, explicit
environments, simulation engines, interventions, observer views, model/debug
views, experiment configuration, provenance, artifacts, and evaluation.

Those terms are conceptual boundaries, not promises that a single universal
class hierarchy will serve every species, modality, or experiment.

## Future extension constraints

Future work should introduce an abstraction only after a concrete experiment
requires it. In particular:

- spatial state must not be coupled to rendering;
- environment state must be explicit when it affects behavior;
- interventions must be recorded as experimental inputs;
- observer-visible and model-internal state must remain separable;
- additional datasets must preserve their own schemas and provenance;
- model complexity must be justified by a scientific question or baseline
  failure;
- population variation must remain explicit about whether it is empirical,
  inferred, calibrated, or generated;
- recorded, derived, inferred, and synthetic information must never be silently
  merged.
