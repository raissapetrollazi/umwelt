# Architecture

This document distinguishes the architecture implemented for Umwelt 0.1 from
the broader architectural direction. The v0.1 modules are intentionally narrow;
they do not freeze future APIs for spatial worlds, interventions, multimodal
data, or additional model families.

## Implemented v0.1 flow

```text
pinned COMPASS files
    -> integrity verification
    -> recorded observation dataset
         |                    |
         |                    +-> replay
         |
         +-> training subjects -> explicit model fit
                                      |
held-out time grids and gaps ----------+
                                      v
                              synthetic observations

recorded evaluation observations -> recorded metrics --+
                                                         +-> comparison -> report
synthetic observations -----------> synthetic metrics --+
```

The held-out observations provide timestamps and missingness masks to the
generator. Their recorded states and activity values are not inputs to model
fitting or state generation.

## Implemented boundaries

### Observation representation

`umwelt.observations` defines source-labeled observations and regular time
series. A series is either recorded or synthetic. Missing state and activity
values must occur together and remain explicit. Dataset containers reject
duplicate subject identifiers and silent source mixing.

### Recorded data adapter

`umwelt.datasets.compass` pins the Zenodo record, expected files, sizes, MD5
checksums, DOI, license, authorship, experimental context, and label semantics.
The adapter pairs activity and sleep rows by timestamp and rejects malformed,
misaligned, negative, or internally inconsistent values.

Raw files are downloaded locally and are not committed to the repository.

### Behavioral model

`umwelt.models.circadian_markov` implements one model family. It has two
computational states, wake and sleep, with first-order transition probabilities
conditioned on daily phase. Observable activity is generated by a phase- and
state-conditioned zero-inflated gamma emission, bounded by the observed training
maximum for its phase/state estimate.

The model pools training subjects. It does not infer subjective state, model
individual differences, or claim that Markov transitions are biological
mechanisms.

### Evaluation

`umwelt.evaluation` independently summarizes recorded and synthetic datasets.
It measures state occupancy, activity distributions, transition frequencies,
bout durations, daily phase profiles, between-subject sleep fraction, and
sleep-state autocorrelation at configured lags. Comparison is descriptive and
contains no implicit validation threshold.

### Experiment configuration and execution

`umwelt.config` strictly validates JSON configuration. Unknown keys are errors,
paths are resolved relative to the configuration file, training/evaluation
subjects must be disjoint, and seeds and model settings are bounded.

`umwelt.experiment` loads the recorded source once, creates the subject split,
fits the model, derives per-series seeds from the master seed, generates
synthetic series, evaluates both categories, and atomically publishes a run
directory. Existing run directories are not overwritten.

### Artifacts and provenance

Each run contains:

- `resolved-config.json` - the exact interpreted configuration;
- `provenance.json` - source, software, split, information categories, and time;
- `model.json` - complete fitted parameters and model assumptions;
- `seeds.json` - master and derived random seeds;
- `synthetic-observations.csv` - explicitly synthetic generated rows;
- `recorded-metrics.json` - metrics computed only from held-out recorded data;
- `synthetic-metrics.json` - metrics computed only from generated data;
- `comparison.json` - descriptive differences between those metric sets;
- `report.md` - readable interpretation boundaries, results, and limitations;
- `artifact-manifest.json` - byte sizes and SHA-256 hashes of the run artifacts.

### Headless interface

`umwelt.cli` exposes dataset download/verification, recorded replay, and complete
experiment execution. It uses only the Python standard library at runtime.
There is no renderer or graphical dependency.

## Preserved conceptual boundaries

Future Umwelt work should remain compatible with recorded data adapters,
observations, replay, behavioral models, synthetic organisms, explicit
environments, simulation engines, interventions, observer views, model/debug
views, experiment configuration, provenance, artifacts, and evaluation.

Those terms are conceptual boundaries, not promises that a single universal
class hierarchy will serve every species, modality, or experiment.

## Future extension constraints

Future work should introduce an abstraction only after a concrete experiment
requires it. In particular:

- spatial state must not be coupled to rendering;
- environment state must be explicit when it affects behavior;
- interventions must be recorded as experimental inputs;
- observer-visible and model-internal state must remain separable;
- additional datasets must preserve their own schemas and provenance;
- model complexity must be justified by a scientific question or baseline
  failure;
- recorded, derived, inferred, and synthetic information must never be silently
  merged.
