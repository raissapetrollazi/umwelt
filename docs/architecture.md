# Architecture Direction

This document describes planned conceptual boundaries for Umwelt. It does not describe an implemented architecture and does not freeze final classes, APIs, storage formats, or command syntax.

Umwelt is expected to grow from small, reproducible scientific milestones rather than from a broad framework designed in advance. Future implementation should keep recorded observations, model assumptions, simulation state, interventions, provenance, and outputs explicit and distinguishable.

## Conceptual Boundaries

Future Umwelt work should remain compatible with concepts such as:

- recorded data adapters for loading specific datasets;
- observations representing measured or annotated behavior from real animals;
- replay for inspecting and analyzing fixed recorded history;
- behavioral models that generate synthetic behavior from explicit assumptions;
- synthetic organisms instantiated from those models;
- environments representing explicit spatial, physical, or contextual state;
- a simulation engine for advancing synthetic organisms and environments;
- interventions for controlled computational perturbations;
- observer views exposing only permitted observable information;
- model/debug views exposing synthetic-model variables for inspection and evaluation;
- experiment configuration for reproducible runs;
- provenance records for inputs, transformations, model settings, interventions, and outputs;
- artifacts produced by replay, simulation, inference, and evaluation workflows;
- evaluation tools for quantitatively comparing recorded and synthetic behavior.

These are planned conceptual boundaries and vocabulary, not current modules, classes, or APIs.

## Replay and Simulation

Replay represents recorded observations from a real experiment. Its history is fixed: researchers may inspect, query, advance through, and analyze it, but they cannot retroactively intervene in what happened.

Simulation represents behavior generated by an explicit computational model. Future simulations may permit environmental intervention, branching, synthetic trajectories, and counterfactual conditions.

Recorded and simulated data must never be silently conflated.

## Observer and Model/Debug Views

An observer view should contain only information plausibly available to an experimental observer or measurement system, such as movement, orientation, observable labels, environmental state, interactions, and recorded physiological or neural measurements when available.

A model/debug view may additionally expose computational variables belonging to a synthetic model, such as hidden state, transition variables, modeled drives, candidate action scores, probabilities, or decision variables.

This separation may eventually allow latent-state inference methods to be evaluated against known synthetic-model state. That computational ground truth belongs to the model; it is not evidence that an equivalent mental state, intention, emotion, drive, or subjective experience exists in a real animal.

## Explicit Worlds Without Required Graphics

A world may be spatially or physically explicit while remaining completely headless. It may contain position, orientation, velocity, trajectories, arena geometry, objects, zones, resources, environmental state, and other animals without any renderer.

Rendering and simulation are separate concerns. Future 2D or 3D visualization must not become a requirement for scientific simulation.

## Planned Scientific Flow

```text
recorded animal observations
    -> replay and analysis
    -> explicit behavioral model
    -> synthetic animal
    -> explicit simulated environment
    -> controlled intervention
    -> quantitative comparison with recorded behavior
```

Synthetic animals should respond to modeled conditions according to explicit behavioral models. Researchers should manipulate modeled experimental conditions rather than directly command synthetic actions.

## Design Constraints

The architecture should remain headless-first, inspectable, reproducible, and explicit about assumptions and provenance. Stochastic procedures should preserve seeds where applicable. Dependencies should be introduced only when justified by a defined scientific milestone.

## Avoiding Premature Structure

Umwelt does not yet define final dataset formats, model APIs, simulation loops, evaluation metrics, command-line commands, or storage schemas. Those choices should follow from concrete research requirements and empirical constraints, beginning with v0.1.
